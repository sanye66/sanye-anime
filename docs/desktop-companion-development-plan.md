本文档只描述桌宠的开发顺序、工程工作、工期、质量门禁和交付风险，不定义用户功能细节。用户可见的产品需求以 [桌宠产品需求](../product/desktop-companion-requirements.md) 为准。

## 1. 计划结论

桌宠不应在当前客户端核心链路之前启动完整实现。建议顺序是：

```text
sanye_anime 客户端核心 MVP
  -> 客户端启动和唤起边界稳定
  -> 桌宠产品原型与视觉资产
  -> 桌宠本地壳层和角色状态
  -> 桌宠到客户端的快速入口
  -> 提醒、设置和异常处理
  -> Windows 安装、升级和发布验收
```

桌宠首版建议采用“轻量桌面窗口 + 角色素材 + 客户端唤起”模式，不一开始建设复杂三维引擎或独立业务后端。

## 2. 范围与工程边界

### 2.1 首版工程范围

- Windows 桌面显示和窗口行为。
- 桌宠角色资源加载、缩放、透明度和动态效果。
- 鼠标点击、双击、右键、拖动和隐藏恢复。
- 本地设置保存和开机启动开关。
- 与 `sanye_anime` 客户端的启动、聚焦、页面唤起。
- AI 快速问答的入口和失败处理。
- 最近内容入口和提醒开关的产品准备。
- 日志、异常退出、安装和卸载验证。

### 2.2 首版不进入工程实现

- 独立桌宠业务后端。
- 独立账户体系、收藏体系和会话存储。
- 长期角色记忆和复杂养成数据。
- 语音、摄像头和持续后台采集。
- 重型三维渲染和高成本动画制作。
- 多平台同时发布。

桌宠使用客户端已有的账户和 AI 能力。桌宠只持有必要的本地状态，不能保存模型密钥、后台管理凭证或完整的用户私密数据。

## 3. 前置门禁

桌宠代码开发开始前，必须先确认：

| 门禁 | 需要确认的内容 | 未确认的影响 |
| --- | --- | --- |
| 产品边界 | 独立运行还是随客户端运行；客户端关闭后是否保留桌宠 | 无法确定启动和退出行为 |
| 平台范围 | Windows 版本、系统缩放和多屏策略 | 无法完成窗口验收 |
| 角色资产 | 静态图、序列帧或动画素材；使用授权和来源 | 无法进入视觉资产制作 |
| 客户端唤起 | 客户端打开方式、已运行时聚焦方式、页面入口 | 无法完成端到端入口 |
| 提醒规则 | 提醒来源、默认状态、安静时段和合并策略 | 可能造成打扰或重复通知 |
| 发布方式 | 安装包、自动更新、卸载和签名策略 | 无法完成分发验收 |

前置门禁未确认时，只做产品、原型和技术验证，不进入正式桌宠实现。

## 4. 开发阶段与工期

| 阶段 | 有效工作日 | 主要工作 | 阶段出口 |
| --- | ---: | --- | --- |
| A 产品与交互冻结 | 3 | 明确桌宠边界、流程、状态、入口和关闭规则 | 产品验收口径确定 |
| B 视觉资产准备 | 4 | 三叶角色素材、晚霞场景、动作清单、静态与动效规格 | 资产可用于原型和开发 |
| C 桌面壳层验证 | 4 | 透明窗口、置顶策略、拖动、停靠、隐藏和退出 | Windows 本地壳层可用 |
| D 角色状态与交互 | 5 | 待机、关注、对话、离线、气泡、右键菜单和设置 | 桌宠本地交互闭环 |
| E 客户端唤起与提醒 | 3 | 首页、AI、最近内容入口；提醒开关和安静时段 | 桌宠到客户端链路通过 |
| F 测试与发布准备 | 3 | 系统缩放、多屏、异常退出、安装卸载和发布清单 | 发布候选版本 |
| **有效工作日合计** | **22** | 不含返工和外部依赖等待 | 进入发布验收 |
| **缓冲** | **5** | 资产修改、系统兼容和安装问题 | 约 27 个工作日总周期 |

单人开发按每天 4 至 6 小时有效工程时间估算。若角色动画、安装签名、自动更新或客户端唤起方式需要反复调整，实际周期可能增加 1 至 2 周。

## 6. 推荐开发顺序

```text
1. 冻结桌宠产品边界和 P0 范围
2. 确认三叶角色与场景资产授权
3. 做透明窗口、拖动、隐藏和退出技术验证
4. 完成待机、关注、离线和右键菜单
5. 完成客户端首页和 AI 唤起
6. 加入设置、开机启动和低打扰提醒
7. 完成 Windows 多分辨率、多屏和安装回归
8. 生成候选安装包，进行发布和回滚验收
```

不建议先做语音、养成、商城或三维效果。桌宠的第一条成功链路应是：

```text
桌面看到三叶
  -> 点击三叶
  -> 选择问问题
  -> 进入客户端 AI
  -> 完成对话
  -> 返回桌面继续陪伴
```

## 7. 测试与质量门禁

### 7.1 功能门禁

- 启动、隐藏、恢复、退出完整可用。
- 单击、双击、右键、拖动互不误触。
- 桌宠可以打开或聚焦客户端首页和 AI 页面。
- 未登录、断网、超时和客户端未启动都有明确反馈。
- 设置立即生效，重启后状态符合用户选择。

### 7.2 系统兼容门禁

- Windows 11 优先验证，兼容 Windows 10 时记录差异。
- 100%、125%、150% 系统缩放均完成验证。
- 单屏和双屏均能找回桌宠。
- 任务栏、全屏应用和窗口切换不会导致桌宠无法关闭。
- 锁屏、睡眠、唤醒和系统重启后的行为符合设置。

### 7.3 打扰与隐私门禁

- 开机启动默认遵循用户选择。
- 主动提醒默认关闭或在首次启动明确征求同意。
- 安静时段内不发送主动提醒。
- 不启用麦克风、摄像头和持续录音。
- 日志不记录完整用户问题、会话内容和凭证。
- 桌宠本地配置可清理，卸载行为有明确说明。

### 7.4 性能门禁

- 待机状态不持续占用高 CPU。
- 动画开启时资源占用稳定，无明显内存增长。
- 桌宠启动不会显著拖慢客户端启动。
- 快速问答超时后能释放请求和界面状态。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 角色素材授权不清晰 | 无法公开发布 | 先做授权清单；未确认时使用内部测试素材 |
| 桌面窗口行为复杂 | 返工和用户无法找回桌宠 | 先做透明窗口技术验证，再开发完整功能 |
| 需求扩展为养成游戏 | 拖慢核心产品 | 养成、商城和多角色列为 P2 |
| 通知过多造成反感 | 用户关闭或卸载桌宠 | 默认低打扰，提醒合并和安静时段优先 |
| 桌宠与客户端状态不一致 | 用户点击后进入错误页面 | 桌宠只负责入口，真实状态由客户端确认 |
| 多屏和缩放兼容问题 | 桌宠消失或位置异常 | 将系统缩放、多屏和唤回列为发布门禁 |
| 单人维护成本过高 | 后续版本难以持续 | 保持桌宠本地状态简单，减少独立业务逻辑 |

## 9. 版本规划

### 桌宠 P0

- Windows 桌面显示。
- 三叶基础角色视觉。
- 待机、关注、对话、离线和睡眠状态。
- 点击、双击、右键、拖动、停靠、隐藏和退出。
- 打开客户端首页、AI 和最近内容。
- 基础设置和异常处理。

### 桌宠 P1

- 收藏更新和番剧排期提醒。
- 安静时段和提醒合并。
- 快捷键唤醒。
- 更多动作和节日主题。
- 客户端主题联动。

### 桌宠 P2

- 语音交互。
- 角色成长和长期记忆。
- 多角色切换。
- 桌面小游戏。
- 高保真三维动画。

## 11. 计划调整结论

桌宠加入整体开发计划后，原有 `sanye_anime` PC Web MVP 仍然是第一优先级。桌宠作为第二阶段增量，预计增加 22 个有效工作日和 5 个工作日缓冲。若需要在首版同时发布桌宠，应将完整公开内容、复杂会话管理、语音、多模态和高级管理运营能力继续后移，不能简单叠加工期。
