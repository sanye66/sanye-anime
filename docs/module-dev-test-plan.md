## 1. 测试工程化基线

### 1.1 Playwright 配置（e2e/ 目录）

```text
e2e/
├── playwright.config.ts        # 项目级配置
├── fixtures/                   # 登录态、测试数据、接口 Mock
├── page-objects/               # 客户端/官网/管理平台页面对象
├── specs/                      # 按板块用例（*.spec.ts）
├── api/                        # API 契约测试（Playwright APIRequestContext）
└── reports/                    # HTML 报告、截图、视频、trace
```

配置要点：

- projects：`client`（1440×900 与 1100×800 两个项目）、`official`、`admin`。
- `trace: 'retain-on-failure'`、`video: 'retain-on-failure'`、`screenshot: 'only-on-failure'`。
- `storageState`：登录态复用（CAS 在测试环境用 Mock 或测试账号签发本地 token）。
- `webServer`：启动 `sanye_client`（5173）与 `sanye_admin`（5175）；后端用测试环境或 Mock。
- CI：合并到 `dev`/`test` 前必须跑 `pnpm e2e:verify`（或 `pnpm e2e:all`）；失败阻止进入 test。
- 定时合成监控：对 staging/prod 用同一套关键用例按 5 分钟/15 分钟周期执行（见监控方案第 6 节）。

### 1.2 分层测试策略

| 层 | 工具 | 覆盖 |
| --- | --- | --- |
| 单元 | JUnit 5 / Vitest | 规则、脱敏、状态机、幂等、缓存键 |
| 集成 | Testcontainers | PG/Redis/ES/RabbitMQ 联调、并发与缓存场景 |
| API 契约 | Playwright APIRequestContext / RestAssured | 接口字段、错误码、鉴权、幂等（对照 api-contract.md） |
| E2E | Playwright | 三端关键用户流程与状态矩阵 |
| 合成监控 | Playwright（定时） | staging/prod 可用性与关键指标 |

### 1.3 测试数据与账号

- 测试环境固定种子：5 部作品（已发布/待审核/草稿/下架各状态）、3 条反馈、2 个会话、测试用户（CAS 测试主体 `e2e-user`）。
- 接口 Mock 场景：ES 不可用（4002）、AI 模型失败（4001）、额度用尽（3002）、下架内容（2003）、未登录（2001）。

**测试**：

| 用例 | 场景 | 断言 |
| --- | --- | --- |
| E2E-C-001 | 打开首页，左侧导航可见 | 首页/AI/我的/设置四个入口存在且可点击 |
| E2E-C-002 | 点击分类切换 | 内容区更新，URL/状态不变 |

### 2.4 S4 AI 工作区（C-P0-06）

**开发要点**：LangChain4j 集成、记忆、RAG（T-E-01/03/04/05/06/07）、前端（T-E-08）。参见技术设计 5.6。

| 用例 | 场景 | 断言 |
| --- | --- | --- |
| E2E-C-017 | 空状态发送第一条问题 | 用户消息出现，流式增量逐步展示，完成后显示操作区 |
| E2E-C-018 | 生成中点击停止 | 状态变为已停止，停止后不再追加文本，可重新生成 |
| E2E-C-019 | Mock AI 失败 4001 | 失败提示+重试；重试不新增第二条用户消息 |
| E2E-C-020 | 断线恢复补拉 | 刷新后调用 `messages?after=`，消息不重复 |
| E2E-C-021 | 推荐卡片→详情 | 卡片点击进入详情，animeId 为已发布作品 |
| E2E-C-022 | 额度用尽（Mock used=limit） | 3002 提示+恢复时间，发送按钮不可重复提交 |
| E2E-C-023 | 新建会话/打开历史 | 标题与选中态联动；删除会话需确认 |
| E2E-C-024 | 剧透模式 | SAFE 下回答不含后续集数关键词（Mock 回答校验） |
| API-004 | `POST messages` | clientMessageId 幂等：重复提交返回原消息，不重复扣额度 |
| API-005 | `POST stop` / `regenerate` | generateTry 递增；停止后 completed 不落库 |

## 3. 执行与门禁

1. 每个任务 DoD 包含：单元/集成测试 + 对应 API 契约用例 + 影响页面的 Playwright E2E 用例。
2. `pnpm typecheck`、`pnpm build`、Java 编译与单测、依赖/密钥扫描全部通过后才允许合并到 `dev`。
3. E2E 报告（HTML/视频/trace）作为发布候选证据归档。
4. 冒烟集合（E2E-C-002/007/012/017/022、E2E-A-003、E2E-O-004）纳入合成监控与发布前回归；
   新增回归集合：E2E-C-021/023/024、E2E-A-008/009/010、E2E-O-005、EVA-001、FAULT-001/002、LAYOUT-001/002
   （对应排期、模型配置、官网正文、内容 CRUD、AI 评测、故障注入/降级、布局双状态）。
