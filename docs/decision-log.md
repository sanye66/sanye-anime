## 1. 已冻结决策

| 编号 | 决策项 | 结果 | 受影响文档 |
| --- | --- | --- | --- |
| D-001 | 客户端形态 | MVP 使用 PC Web，优先支持 Windows；Electron 延后 | 产品需求文档、版本基线 |
| D-002 | 产品端划分 | 客户端、官网和管理平台作为独立产品端 | 产品总体架构 |
| D-003 | 官网范围 | 提供公开入口、法律信息、帮助和选定的公开信息；不提供完整 AI 工作区 | 产品总体架构、开发计划 |
| D-004 | 账户边界 | 使用统一产品账户概念；允许匿名浏览公开内容；私有数据需要登录 | 产品需求文档、功能详细说明 |
| D-005 | AI 可用范围 | MVP 的 AI 只属于客户端能力；官网只展示介绍 | 产品总体架构 |
| D-006 | AI 额度 | 初始默认匿名用户每日 5 次、登录用户每日 30 次；额度可配置 | 产品需求文档、功能详细说明 |
| D-007 | 后端形态 | MVP 使用模块化单体；没有明确运维收益时不拆分服务（已被 D-024 覆盖） | 开发计划、技术架构 |
| D-008 | 搜索范围 | 首先使用 Elasticsearch 完成全文和结构化搜索；向量检索列为 P1 | 技术架构 |
| D-009 | 数据规模 | 首先使用一个 PostgreSQL 实例；MVP 不做读写分离和分库分表 | 技术架构 |
| D-010 | 消息处理 | 使用持久化消息，最多重试 3 次并处理死信；MVP 不依赖延迟队列 | 技术架构 |
| D-011 | 部署基线 | 本地和测试使用 Docker Compose；首个生产版本使用单节点容器部署 | 技术架构、版本基线 |
| D-012 | 管理边界 | RuoYi 作为独立内部平台，使用基于角色的访问控制和审计记录 | 产品总体架构、技术架构 |
| D-013 | 内容发布 | 只有经过审核并已发布的内容才能被客户端或官网看到 | 产品总体架构、功能详细说明 |
| D-014 | 外部链接 | 只允许经过审核的合法链接；不提供未授权的播放、下载或资源聚合 | 产品需求文档、产品总体架构 |
| D-015 | 管理后端边界 | RuoYi 后端独立放置于 `sanye_admin_server`，业务后端继续放置于 `sanye_server`；管理平台前端 `sanye_admin` 作为独立前端原型演进 | 技术架构、差距登记表 |
| D-016 | 桌宠范围 | 桌宠作为 `sanye_anime` 的 P1 附属形态，Windows 优先；首版只做桌面显示、角色状态、低打扰交互、客户端唤起和基础设置，不独立建设业务后端 | 桌宠产品需求、桌宠开发计划、产品总体架构 |
| D-017 | 搜索与仓库边界 | 客户端顶部搜索进入搜索结果页，承接关键词查询；番剧仓库保留为“浏览全部作品”页面，承担全部作品浏览与组合筛选 | 功能详细说明、原型评审记录 |
| D-018 | MVP 冻结基线 | 客户端、官网、管理平台三端 P0/P1/P2 边界以 [MVP 冻结清单](../product/mvp-freeze.md) 为基线；作品比较裁决为 P2；管理平台任务管理 P0 只含查看、立即执行与重试；冻结期内新增需求默认进入 P1/P2 | 产品需求文档、功能详细说明、MVP 冻结清单 |
| D-019 | 产品文档冻结基线 | `product/` 文档按 2026-08-18 版本冻结：三个入口原型与页面状态矩阵、MVP 冻结清单一致；作品比较为 P2、深色主题为 P1、剧透模式默认避免剧透为 P0 回答规则；产品文档不含 API、数据库、部署与版本技术细节 | 产品文档目录、页面状态矩阵、MVP 冻结清单 |
| D-020 | 认证方案 | 客户端与官网认证使用 CAS 单点登录（Apereo CAS，协议 v3 serviceValidate）；业务端在 ticket 校验后签发本地 JWT/Redis 会话凭证，API 鉴权与即时吊销由本地凭证负责；管理平台首版保留 RuoYi 内部账号，是否接入 CAS 待评审 | 技术架构、详细技术设计、版本基线 |
| D-021 | AI 编排方案 | AI 服务使用 LangChain4j 实现模型调用、会话记忆（Memory）与 RAG 检索；记忆持久化到 PostgreSQL，RAG 先使用 ES BM25 经典检索，Embedding/向量检索列为 P1 | 技术架构、详细技术设计、版本基线 |
| D-022 | 测试与监控方案 | E2E 测试使用 Playwright（三端项目 + API 契约测试 + 合成监控）；全系统监控使用 Prometheus + Grafana + Alertmanager + 各中间件导出器，覆盖基础设施、应用池化资源、业务、AI 成本与前端指标 | 版本基线、按板块开发与测试方案、全系统监控方案 |
| D-023 | 任务分支命名 | 因仓库存在历史 `feature` 分支（Git 不允许同名前缀），任务分支暂用 `feature-<task>` 连字符形式；`feature` 分支归档后恢复 `feature/<task>` | 开发任务清单、AGENTS.md |
| D-024 | 微服务架构基线 | 项目按微服务架构建设：`sanye_gateway` 网关 + `sanye_auth`、`sanye_anime`、`sanye_search`、`sanye_ai_chat`、`sanye_favorite`、`sanye_file`、`sanye_feedback`、`sanye_job` 八个业务服务 + RuoYi 管理端；服务间通过 OpenFeign 与事件通信，Nacos 注册与配置，Sentinel 限流熔断，Redis 共享缓存，单 PostgreSQL 实例按服务独立 schema（服务间不跨 schema 直连）；网关统一入口、鉴权前置与路由。覆盖原 D-007（模块化单体）与 D-011（单节点容器部署）作为首版基线，开发计划工作量按新基线重新估算 | 技术架构、详细技术设计、版本基线、开发计划、开发任务清单 |
| D-025 | 前端与全工程范围 | 前端工程（`sanye_client` 客户端+官网、`sanye_admin` 管理前端）纳入首版并统一经网关对接；前端工程化基线（请求层、CAS 登录态、SSE 客户端、错误与 Web Vitals 上报、静态托管）在 T-B-08 落地；`sanye_deploy` 负责部署与监控配置，`sanye_website` 为过渡目录不参与构建，桌宠列为 P1 | 技术架构、详细技术设计、开发计划、开发任务清单 |
| D-026 | 桌宠技术选型与边界冻结 | 桌宠作为 `sanye_pet` 应用进入实现：Electron（透明无边框置顶窗口 + Tray + IPC）+ Vite/TypeScript/Vue 3 渲染层；窗口只显示原创角色和互动按钮，不绘制场景背景；角色为原创矢量三叶（短发/红色结绳/蓝底白四叶草和服/红腰带/侧背包/棕眸），动作用 Web Animations/CSS 实现，避免第三方版权素材；客户端启动后自动拉起桌宠，重复启动复用单实例，不默认独立常驻启动；首发 Windows（11 优先、10 记录差异）；开机启动与主动提醒默认关闭；AI 快速问答首版唤起客户端 AI 页，桌宠内仅轻量气泡；客户端唤起地址可配置（开发默认 `http://localhost:5173`） | 桌宠产品需求、桌宠开发计划、开发任务清单、桌宠测试报告 |

## 2. 外部门禁

以下事项无法仅通过当前仓库确认，因此必须作为明确门禁保留，不能被默认视为已满足：

| 编号 | 门禁 | 必需证据 | 阻塞范围 |
| --- | --- | --- | --- |
| G-001 | AI 供应商和模型 | 供应商协议、模型名称、SDK 兼容性、成本上限和速率限制 | 生产环境 AI 发布 |
| G-002 | 内容和图片版权 | 来源清单、许可证或授权记录、允许使用的字段和下架联系人 | 公开内容发布 |
| G-003 | RuoYi 兼容性 | 独立启动、登录、角色授权和业务协作验证 | 管理平台发布 |
| G-004 | 版本兼容性 | 使用版本基线完成最小服务构建和启动 | 代码实现基线 |
| G-005 | 基础设施安全 | 固定镜像扫描和 Docker 服务配置审查 | 测试和生产部署 |
| G-006 | 公开运行环境 | 域名、托管、TLS、备份位置和支持联系人 | 官网发布 |
| G-007 | 视觉设计资产 | 高保真页面、可复用组件、品牌资产和响应式评审 | UI 优化和视觉验收 |
| G-008 | 桌宠角色资产授权 | 三叶角色、和服人物、动画和安装包内素材的授权或内部测试使用边界 | 桌宠公开发布 |
| G-009 | Windows 桌面发布能力 | 安装包、代码签名、开机启动、自动更新、卸载和多屏缩放验证 | 桌宠 Windows 发布 |

## 3. 变更规则

1. 修改已冻结决策时，必须记录原因、受影响文档、迁移影响和回滚方案。
2. 外部门禁必须附带证据后，状态才能变更为 `passed`。
3. 临时开发值必须标记为 `development-only`，不能无记录地变成生产默认值。
4. 产品范围变更进入 P1 或 P2，除非它能够消除 P0 风险或修复发布阻塞项。
5. 决策记录必须和受影响文档在同一次变更中同步更新。
