## 1. 版本策略

- 分支：`feature-<task>`（任务）→ `dev`（日常集成）→ `test`（验收）→ `release`（稳定基线）。
- 版本号：`0.1.0-SNAPSHOT`（开发）→ `0.1.0`（首个发布）→ 语义化版本 `MAJOR.MINOR.PATCH`。
- 变更类型：feat → MINOR；fix/安全 → PATCH；破坏性/范围变化 → MAJOR（登记 decision-log）。
- 每个发布版本对应一次发布记录（§6）与回滚基线（§5）。

## 2. 发布类型

| 类型 | 目标 | 门槛 |
| --- | --- | --- |
| 内部预览 | local/dev | 冒烟 + 三端构建 |
| 验收发布 | test | CI 全绿 + 接口体检 + E2E + 已知问题清单 |
| 正式发布 | release/prod | 发布检查清单全过 + 回滚演练 + 备份确认 |

## 3. 发布流程

```text
任务分支完成（development-tasks 证据）
   → CI 全绿（typecheck/build/mvn test/扫描）
   → 合并 dev（合并门禁）
   → 验收测试（冒烟/E2E/体检/按钮）
   → 合并 test，运行验收
   → 发布检查清单（§4）
   → 打 release + 部署
   → 发布后验证（§6）→ 登记发布记录与已知问题
```

## 4. 发布检查清单

发布前逐项确认：

- [ ] 全量回归通过：`mvn test`（含覆盖率）、`pnpm typecheck/build`、冒烟 0 失败、
  E2E 0 失败、接口体检 0 失败、按钮体检 0 失败。
- [ ] 迁移确认：本版本所有 Flyway 迁移已按顺序执行且无失败；备份已通过独立恢复及应用验证，不能仅以备份生成成功认定可用。
- [ ] 配置确认：环境变量按 environment-config 设置；关键配置已按严格环境规则注入并实际连接验证；CORS 收敛。
- [ ] 安全确认：密钥扫描（Gitleaks）0 命中；依赖扫描高危 0；日志脱敏复核；法律文案（GAP-013）状态明确。
- [ ] 兼容确认：接口契约（api-contract）与实现一致；数据库变更向后兼容；前端构建产物含最新静态资源。
- [ ] 回滚就绪：回滚方案（§5）明确；上次 release 基线可恢复。
- [ ] 已知问题：gap-register / 已知问题清单已更新，无 P0 未解决项。

## 5. 回滚计划

T-R-06 使用 [CI/CD 候选镜像入口](./ci-cd.md#t-r-06-候选镜像与实例核验) 生成不可变摘要清单；部署计划必须指定不同提交的上一发布清单、备份恢复证据和迁移兼容评审材料。`bind-config.mjs` 把这些材料与配置指纹绑定，不能替代材料内容的审核。候选 `candidate.json` 包含 Flyway SQL 摘要，应与上一候选逐项比较；已执行迁移不能修改，新增迁移必须说明旧应用是否仍能读取更新后的 schema。

若兼容，可在同一项目、网络和数据卷上恢复上一套 `release.json`、`compose.json` 与相应配置版本，再执行实例核验和业务回归。若不兼容，停止自动应用回滚，按 [独立恢复说明](./backup-recovery.md) 向隔离目标恢复并验收，不能对原库执行反向迁移或覆盖恢复。真实测试部署与一次实际回滚属于 T-R-07，当前没有这一轮完整发布证据。

| 层 | 回滚方式 | 验证 |
| --- | --- | --- |
| 应用 | 回退到上一 release 镜像/jar（保留数据） | 健康检查 + 冒烟 |
| 数据库 | 禁止反向迁移：先备份，向前修复（新增迁移）或恢复备份 | pg_restore 演练（ops-runbook） |
| 配置 | 还原上一版本环境变量（密钥轮换需同步撤销） | 服务启动日志 |
| 前端 | 回退静态资源版本（nginx 目录切换） | 页面冒烟 |

回滚触发条件：P0 缺陷、数据损坏、安全事件、核心链路不可用且 15 分钟内无法修复。
