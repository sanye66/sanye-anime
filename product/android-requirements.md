更新记录：2026-10-09，v0.46，把「画面在放大态也不能把提示吞掉」「竖屏要能换集」「播放进度只认往前走」写成验收条件（VQ-61），并补齐样式自然度的两条口径。其一，放大/全屏时舞台覆盖整个视口，任何必须让用户看到或操作的信息（播放失败、来源不可用、缓冲、换线、后台恢复）都必须渲染在画面内，并带对应的「切换线路／重试当前线路／继续播放」入口；实测此前舞台外的错误块被完全盖住，用户只看到黑屏且无从操作。其二，竖屏必须能换集与静音：画质与帧率档位仍只在放大后选择（口径不变），但下一集、选集、音量不得因为竖屏而消失（此前换集必须先横屏）。其三，首帧之后的卡顿要有兜底与提示：出过画面后再定格不得无限等待播放内核默认超时，必须给出「网络较慢，正在缓冲…」并在限定时间内按线路失败处理。其四，播放进度只认往前走：同一集已有进度明显靠前时，换线路或自动回退起播产生的开头几秒记录不得覆盖它；续播要按同一集取最靠前的进度，不因换了线路就从头开始；中途被系统打断的拖动（来电、手势）要回到拖动前的位置，不把预览位置当成用户选择。其五，样式自然度：界面图标必须是同一套线性图形（不依赖系统字体或 emoji 回退），颜色与字号走统一令牌；挂载失败兜底页在三套外观下都必须有实心卡面与边框，不得只剩文字。其六，音量随设置保留：音量属于用户偏好，重启后必须保持，不得每次回到 100%；「我的」需要提供清理媒体缓存（含内存分片缓存）的入口。验收：新增 `e2e/android-playback-resilience.test.cjs` 8 项（放大态错误可见且可重试、首帧后缓冲提示、后台恢复入口、拖动取消回位、音量落盘、清理媒体缓存、跨线路续播与开头几秒覆盖保护、随包线路重试与 HLS 移动端参数），安卓门禁 15 个文件 55 项 55 通过 0 跳过 0 失败；原生 JVM 单测 31 项 30 通过／1 跳过／0 失败；`pnpm typecheck` 通过。边界：本轮无视觉模型可用，样式结论来自计算样式与像素量测（截图与报告在 `sanye_deploy/.local/android-style-review/`，未经人工看图确认）；真机触控与系统字体放大仍待环境；本轮未重新打包，现有交付仍为 v66。

更新记录：2026-10-09，v0.45，把「来源不可用时要说清楚」与「读取不能永远停在读取中」写成验收条件（VQ-60）。其一，公开来源取不到内容时必须提示「暂不可用，可稍后重试」，不得显示成「没有找到匹配作品」：用户此前看到「没有找到」只会认为来源里没有这部作品，而实际情况是来源页面取不到（网络或站点问题），两者对用户的下一步动作完全不同；本机片库不受影响，检索失败也不清空已有结果。其二，等待要有尽头并给出出路：片库、观看历史、设置读取都必须有上限，超时按失败处理并允许重试，不得让页面永久停在「正在读取」；写入在途时也不允许把界面留在模糊地等待状态。其三，播放进度不能因为一个无关字段丢失：封面地址不合规时只丢弃封面，进度本身照常保存（用户不应因为来源换了一张图就丢掉看到哪一集）。验收：新增断言「来源不可用时静默重试一次并提示暂不可用，而不是显示没有找到」（`e2e/android-search-retry.test.cjs`），安卓门禁 14 个文件 47 项 47 通过 0 失败；`pnpm typecheck` 通过。边界：真机耗时与真实来源站点表现仍待环境；本轮未重新打包，现有交付仍为 v66。

更新记录：2026-10-08，v0.44，按用户「现在有些按钮的响应方式与速度存在不合理的地方，进行优化」把按钮的响应方式与速度写成可复核的验收条件并全部达成。其一，按住即有反馈：此前样式表里**没有任何按钮的 `:active` 规则**，触摸反馈只剩 WebView 松手后闪一下的默认灰罩（实测导航片库、顶栏主题切换、搜索入口、首页作品卡四个抽样在按住 60ms 期间计算样式「无任何变化」，默认可点高亮 `rgba(0,0,0,.18)`、`transition: all 0s`），`touch-action` 也是默认 `auto`（存在双击缩放等待）；现在按下当帧就有轻微缩放与透明度反馈（80ms 收尾）、默认高亮关掉、页面 `touch-action: manipulation`、按钮不再被长按选中。按下反馈不依赖浏览器给 `:active` 的时机（合成触摸实测按住 160ms 都还没命中 `:active`，真机上可滚动页面同样可能晚一拍），改由按下事件直接挂按下态、抬起或取消即复位，触摸按下实测进入按下态且抬起复位。其二，操作先本地生效：主题切换与播放速度原先要等原生写入返回才更新界面（原生写入 180ms 时实测 198ms 才变色），片库收藏要等收藏写入返回（实测 187ms）；现在都先按用户操作更新界面、写入失败回滚并说明，且不会出现并发写入时旧结果覆盖新状态（原生写入 300ms 时实测 3–4ms 内生效）。其三，同一动作不重复执行：连点两次收藏会真的写两次原生、连点两次「保存到本机」会在本机片库留下两条同地址作品（实测各 2 次）；现在写入在途时拦截重复点击，实测各 1 次。其四，检索不再被静默丢弃：旧检索在途时改关键词，输入即搜的调用会被直接丢弃——实测输入框显示「第二」而列表仍是「第一」的结果、桥接只收到一次检索；现在同一关键词不重复打来源、不同关键词直接取代旧检索，实测两次都发出。其五，破坏性动作不再用原生对话框：清除观看历史从 `window.confirm` 改为同一颗按钮的应用内两步确认（第一次点变成「再点一次确认清除」并用危险色标出、3 秒不点自动复位、清除期间按钮禁用），实测第一次点不写原生、确认后只清除一次、`window.confirm` 调用 0 次。验收：新增 `e2e/android-button-response.test.cjs`（5 项）并加入 `.github/workflows/android-check.yml`，安卓门禁 14 个文件 46 项 46 通过 0 跳过 0 失败；`pnpm typecheck`、`pnpm build` 通过；量测脚本 `sanye_deploy/.local/measure-button-response.cjs` 与改前/改后报告 `sanye_deploy/.local/android-button-response/{before,after}.json`、门禁证据 `gate-*.json` 已留存；全量审计仍是 234 个场景问题种类 0、问题实例全部为已锁定取舍。本轮只改前端（Vue/CSS），未重新打包，现有交付仍为 v66。真机触控手感仍待环境。

## 1. 已确认边界

Windows 与安卓各自独立使用，安卓无需电脑开机、无需连接 Windows 客户端，也不要求用户购买服务器。两端个人数据各自保存，不默认同步。在线搜索、更新和在线观看视频仍需互联网。

本文是安卓专项草案。用户确认安卓功能和交互决策参考现有 PC 版，并要求推进全部功能；不能把下文的首版建议视为删减授权。PC 的 Java、PostgreSQL、网关与桌面专用功能不构成手机运行依赖，Android 等价能力需要独立实现和验收。未实现的功能必须如实显示不可用，不能用演示数据或网页套壳代替。

画质与帧率的浮层列表的**尺寸与文案是锁定项**：宽度与触发它的按钮等宽，行高、内外边距与字号固定，不随选中项、可选项数量或自动降级状态变化；列表只用**高亮**表达当前实时生效的挡位，不写「已降到某档」「生效」之类文字说明，也不恢复勾选列。档位因设备预算或来源限制被自动升降时，列表高亮必须跟着实时档位走，而不是停在用户请求的档位上。

按钮的**响应方式与速度是锁定项**：每个可点元素在按住当下就要有可见反馈，松手后立即生效；界面状态由用户操作决定，不等网络往返或原生写入返回（写入失败必须回滚到原状态并说明原因），同一动作在写入在途时重复点击只允许执行一次，不得产生重复数据或重复的清空。界面内不得用会冻结页面的浏览器原生对话框（`confirm`／`alert`）做确认：破坏性动作（清除观看历史这类）改用同一处的二次确认，并给出不确认时自动复位的时间。

完整目标是把 PC 客户端用户能操作的首页、番剧仓库、搜索、作品详情、选集与播放、收藏与观看历史、一周排期、设置、反馈及 AI 等功能，以安卓独立可运行的前端和数据/业务能力交付。不能用只有标题和网址的独立小页面、可编译的空库或换了图标的 APK 冒充 PC 等价客户端。PC 独立的 RuoYi 管理平台不是桌面客户端界面；如需在手机上管理后台，须另外明确管理员身份、权限与交付入口。

## 3. 完整使用链路

下列是对现有首版建议的细化，不表示 Windows 全部功能已承诺移植。

| 场景 | 正常过程 | 异常后可继续的操作 |
| --- | --- | --- |
| 搜索后直接看 | 搜索 → 进入播放器置顶的观看页 → 下方作品信息和选集/线路，不强制先保存作品 | 搜索位置保留，可重试或换受支持线路；失败不产生假观看记录 |
| 保存作品 | 搜索结果或作品地址 → 预览 → 明确保存 → 仓库与详情可见 | 失败保留原数据，重复操作不重复建档 |
| 收藏与回看 | 任意作品入口收藏 → 我的收藏 → 同一作品详情 | 收藏失败恢复原状态，其他页面不会显示假成功 |
| 继续观看 | 播放 → 暂停/关闭 → 我的历史 → 对应集数继续 | 来源失效保留历史；不支持精确续播的线路明确说明，不跳错集 |
| 更新与排期 | 查看已有作品 → 刷新 → 新信息出现在详情/排期 | 无网络保留最后有效数据和时间，不把旧内容显示为刚更新 |
| 清理与升级 | 清理媒体缓存或覆盖升级 → 返回应用 → 收藏和历史仍在 | 数据恢复失败显示原因，不自动清空个人数据 |

收藏、保存作品和观看历史是不同动作：直接观看不会自动加入番剧仓库；收藏尚未保存的作品会保留必要作品信息。查看预览不算已观看；取消收藏不删除观看进度，删除历史不取消收藏。不能控制播放进度的外部线路只展示其实际支持的能力。

## 4. 产品验收

- 电脑关闭时仍能启动、浏览本地数据；手机有网络时完成支持来源的搜索到播放。
- 断网、搜索无结果、来源失效、导入失败和本地空数据各有状态与恢复入口。
- 收藏、设置和已保存进度在重启与系统回收后保留，不同集数和线路不串用进度。
- 返回、旋转和后台恢复不产生重复播放或跳错集；覆盖升级保留个人数据。
- 每个可点元素按住当下就有可见反馈、松手立即生效；主题、收藏、播放速度这类界面状态先按用户操作生效，原生写入失败时回滚到原状态并说明。
- 同一动作在写入在途时重复点击只执行一次：不会保存出两条同地址作品、不会重复清空；清除观看历史这类破坏性动作在界面内二次确认完成，不弹原生对话框。
- 放大/全屏时画面内必须有全部必要反馈：播放失败、来源不可用、缓冲、换线、后台恢复都在画面内可见并带对应操作入口；竖屏保留换集、选集与音量，画质与帧率仍只在放大后选择。
- 播放进度只往前走：换线路或自动回退起播产生的开头几秒不得覆盖同一集已靠前的进度；续播按同一集最靠前的进度落位；被系统打断的拖动回到拖动前的位置；音量随设置保留，重启后不跳回 100%。
