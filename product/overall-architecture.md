## 技术工程映射

产品端和技术工程不是同一层概念。产品上保留 `sanye_anime` 客户端、`official` 官网和管理平台三个使用入口；技术上统一落在以下三个核心工程中：

| 技术工程 | 框架 | 承载范围 |
| --- | --- | --- |
| `sanye_server` | Spring Boot / Spring Cloud Alibaba | 账户、动漫内容、搜索、AI、文件、反馈和任务等服务端能力 |
| `sanye_client` | Vue 3 / TypeScript / Vite | PC 客户端页面，以及官网公开页面和路由 |
| `sanye_admin` | RuoYi / Vue 3 / Element Plus | 内容管理、审核发布、运营、权限、任务和审计 |

`sanye_deploy` 是部署辅助目录，不属于核心业务工程；`sanye_website` 是早期独立官网骨架的迁移过渡目录，官网产品名称以 `official` 为准。

## 1. 架构目标

项目划分为三个产品应用：

```text
访客
  |
  v
official 官网  <------>  sanye_anime 客户端
  ^                           ^
  |                           |
  +-------- 公开内容 -------+

运营人员
  |
  v
管理平台
  |
  +--> 内容、用户、AI、运营和审计管理
```

三个应用面向不同用户，并承担不同职责：

| 应用 | 主要用户 | 产品职责 | 访问边界 |
| --- | --- | --- | --- |
| `sanye_anime` 客户端 | 动漫观看者和 AI 用户 | 内容发现、作品详情、AI 对话、收藏和个人历史 | 面向用户的产品体验 |
| `official` 官网 | 访客、潜在用户、合作方和搜索访问者 | 品牌展示、公开信息、下载或入口引导、帮助和法律信息 | 仅限公开信息 |
| 管理平台 | 内容编辑、运营人员、客服人员和管理员 | 内容发布、用户支持、AI 运营、任务监控和审计 | 仅限内部授权人员 |

`sanye_anime` 是核心产品，`official` 是公开入口，管理平台是运营和治理中心。

## 2. 产品总体分层

```text
展示层
├── 客户端
├── 官网
└── 管理平台

共享产品能力层
├── 身份与账户
├── 动漫内容
├── 搜索与推荐
├── AI 对话
├── 文件与图片资源
├── 反馈与通知
└── 使用和运营记录

治理层
├── 内容审核与发布
├── 权限管理
├── 隐私与数据管理
├── AI 安全与质量审查
├── 任务管理
└── 审计与事件处理
```

展示层可以独立发布，但共享产品能力必须遵循统一的内容、账户、权限和数据规则。

## 3. 客户端架构

### 3.1 产品定位

客户端是供用户反复使用的 PC 核心产品，将动漫浏览和 AI 动漫助手结合起来，支持长时间使用、键鼠操作、多栏信息展示，以及内容工作区和 AI 对话之间的快速切换。

### 3.2 主导航

```text
客户端
├── 首页
├── AI
└── 我的
```

客户端外壳还包含全局搜索、最近访问、用户状态、通知和设置。

### 3.3 客户端模块

| 模块 | 主要功能 | 优先级 |
| --- | --- | --- |
| 首页 | 精选内容、日漫、剧场版、Banner、榜单、排期和内容分区 | P0 |
| 搜索 | 动漫、别名、角色、类型和标签搜索 | P0 |
| 作品详情 | 基础信息、简介、标签、角色、排期、相关作品、收藏和进入 AI | P0 |
| AI | 新建会话、动漫问答、推荐、剧透模式、流式回答、停止、重试和推荐卡片 | P0 |
| 会话历史 | 打开、重命名、归档、删除和搜索会话 | P0/P1 |
| 我的 | 资料、收藏、浏览记录、AI 历史、设置、隐私和反馈 | P0/P1 |
| 通知 | 系统通知、内容更新、任务结果和重要账户消息 | P1 |
| 桌宠 | 桌面陪伴、快速唤起、最近内容、角色状态和提醒入口 | P1 |

### 3.4 客户端主流程

```text
打开客户端
  -> 浏览首页
  -> 搜索或选择作品
  -> 打开作品详情
  -> 带作品上下文询问 AI
  -> 接收回答和推荐卡片
  -> 打开其他作品详情或继续对话
  -> 保存收藏或会话历史
```

### 3.5 客户端边界

客户端可以：

- 展示已发布内容和用户自己的数据。
- 提交搜索、对话、收藏、反馈和设置操作。
- 展示 AI 回答、安全提示、加载状态和错误。
- 在本地保留临时草稿和页面状态。

客户端不可以：

- 管理未发布内容。
- 自行决定权限或用户额度。
- 保存模型凭证或内部运营配置。
- 将未经确认的 AI 内容作为权威动漫信息。

### 3.6 桌宠产品边界

桌宠属于客户端附属形态，不新增第四个核心产品工程。它负责桌面显示、角色状态、轻量交互和客户端唤起；客户端负责账户、动漫内容、AI 会话、收藏、历史和反馈。

```text
桌宠
  -> 打开或聚焦 sanye_anime 客户端
  -> 进入 AI 页面
  -> 恢复最近内容
  -> 展示允许的轻量提醒
```

桌宠不得绕过客户端和服务端的权限规则，不保存模型凭证，不默认启用麦克风、摄像头或持续录音。首发 Windows 优先，复杂养成、语音和高保真三维能力列为后续版本。

## 4. 官网架构

### 4.1 产品定位

`official` 是面向公众的产品，用于说明 sanye_anime 是什么、吸引访客、提供可信的公开信息并引导用户进入客户端；即使不登录也必须具备基本使用价值。

官网不复制完整客户端体验，MVP 阶段不将其扩展为第二套管理系统或第二个完整 AI 应用。

### 4.2 官网模块

| 模块 | 主要功能 | 优先级 |
| --- | --- | --- |
| 公开首页 | 产品定位、核心价值、客户端入口和选定的公开内容 | P0 |
| 产品介绍 | 客户端功能、AI 动漫助手介绍和使用场景 | P0 |
| 公开动漫内容 | 选定作品、热门榜单和公开排期信息 | P1 |
| 下载或进入 | PC Web 入口、桌面版本发布后的下载引导和版本信息 | P0 |
| 帮助中心 | 新手指引、账户帮助、AI 使用规则和常见问题 | P1 |
| 公告 | 产品公告、维护通知和内容政策变更 | P1 |
| 法律与隐私 | 隐私政策、使用条款、版权声明和联系信息 | P0 |
| 反馈与联系 | 公开联系渠道和问题反馈引导 | P1 |

### 4.3 官网主流程

```text
访客打开官网
  -> 了解产品价值
  -> 浏览选定的公开信息
  -> 阅读使用、隐私或版权规则
  -> 进入客户端或按照下载引导操作
```

### 4.4 官网边界

官网可以：

- 展示已发布的公开内容。
- 提供产品、帮助、公告、法律和联系信息。
- 引导访客进入客户端和账户入口。

官网不可以：

- 展示私有对话、收藏或浏览记录。
- 不经过管理平台审核流程直接发布内容。
- 暴露内部任务状态、用户数据、AI 提示词或运营配置。
- 承诺未授权的观看、下载或资源聚合。

## 5. 管理平台架构

### 5.1 产品定位

管理平台是内部运营平台，用于维护内容质量、处理用户和 AI 反馈、控制产品配置、监控定时任务并保留运营记录。

管理平台不是面向用户的客户端版本，应优先保证准确性、权限边界、批量操作、审核状态和可审计性。

### 5.2 管理角色

| 角色 | 主要职责 | 典型权限 |
| --- | --- | --- |
| 超级管理员 | 平台配置和紧急权限处理 | 所有模块和高风险操作 |
| 内容编辑 | 动漫、角色、标签、Banner 和排期 | 内容编辑和提交 |
| 内容审核员 | 审核、发布、下架和驳回内容 | 内容审核和发布 |
| AI 运营 | AI 提示词、模型配置、质量审查和安全案例 | AI 运营和评测 |
| 客服运营 | 用户反馈、举报和账户协助 | 用户支持和反馈 |
| 数据运营 | 数据同步、搜索重建和数据修正 | 数据任务和任务结果 |
| 审计员 | 只读运营和安全审查 | 审计记录和报告 |

单人开发期间，一个人可以承担多个角色，但进入生产使用前必须保留清晰的权限边界。

### 5.3 管理平台模块

| 模块 | 主要功能 | 优先级 |
| --- | --- | --- |
| 仪表盘 | 产品使用、内容状态、AI 使用、错误和待办工作 | P0 |
| 内容管理 | 动漫、别名、类型、角色、排期、榜单、Banner 和相关作品 | P0 |
| 内容审核 | 草稿、审核、发布、驳回、下架和变更历史 | P0 |
| 用户管理 | 用户状态、资料支持、登录风险和数据请求 | P0 |
| 对话与反馈 | AI 回答反馈、用户举报、处理状态和结果记录 | P0 |
| AI 运营 | 模型可用性、额度规则、提示词版本、安全规则和评测结果 | P1 |
| 搜索与推荐 | 搜索状态、推荐配置和重建请求 | P1 |
| 文件与资源管理 | 图片审核、使用关联、版权证据和无效资源清理 | P1 |
| 任务管理 | 排期同步、索引维护、缓存刷新、清理、重试和执行记录 | P0/P1 |
| 系统配置 | 公开设置、功能开关、公告和客户端配置 | P1 |
| 权限与审计 | 角色、权限、高风险操作、变更历史和审计记录 | P0 |

### 5.4 管理平台主流程

```text
内容编辑创建或更新内容
  -> 审核员检查内容和来源证据
  -> 内容发布
  -> 客户端和官网展示已发布内容
  -> 收到用户反馈或数据问题
  -> 运营人员处理问题
  -> 保留审计记录和后续结果
```

### 5.5 管理平台边界

管理平台可以：

- 创建、审核、发布、更新和下架内容。
- 处理用户反馈和 AI 质量案例。
- 在授权范围内配置产品规则。
- 启动、重试或查看定时任务。
- 根据角色权限查看运营记录。

管理平台不可以：

- 在常规发布中绕过内容审核。
- 直接向普通用户暴露内部数据。
- 没有记录原因和权限就修改用户数据。
- 用未经验证的 AI 回答替代来源证据。
- 允许所有运营人员访问全部个人或安全敏感数据。

## 6. 共享产品能力边界

| 能力 | 客户端 | 官网 | 管理平台 |
| --- | --- | --- | --- |
| 已发布动漫内容 | 读取 | 读取选定的公开内容 | 创建、审核和管理 |
| 用户账户 | 使用自己的账户 | 入口和公开引导 | 按权限管理 |
| AI 对话 | 创建和管理自己的对话 | 仅可选的公开演示 | 审查、配置和审计 |
| 收藏和历史 | 读取和修改自己的数据 | 不提供 | 按权限支持查询 |
| 反馈 | 提交并在支持时查看自己的状态 | 提交公开联系信息 | 处理并关闭 |
| 文件和图片资源 | 查看授权资源并提交允许的上传 | 查看公开资源 | 审核、替换和清理 |
| 排期和榜单 | 读取已发布结果 | 读取选定的公开结果 | 维护来源和发布状态 |
| 任务 | 不直接访问 | 不直接访问 | 按权限启动、查看和重试 |
| 审计记录 | 不访问内部记录 | 不访问 | 按角色读取和管理 |

## 7. 内容与发布生命周期

所有公开内容遵循统一的发布生命周期：

```text
草稿
  -> 提交审核
  -> 审核通过
  -> 已发布
  -> 更新或下架
  -> 已归档
```

规则：

1. 只有 `Published` 内容可以出现在客户端或官网。
2. 内容更新必须保留上一版本和变更原因。
3. 下架内容必须在约定的产品窗口内从公开入口消失。
4. 内容来源、图片来源、审核结果和操作人员必须可追溯。
5. AI 推荐只能引用当前用户可见的内容。

## 8. 账户与访问关系

三个应用使用统一的产品账户概念，但访问级别不同：

```text
访客
  -> 官网公开内容

注册用户
  -> 客户端个人功能和 AI 额度

授权运营人员
  -> 按角色访问管理平台
```

官网可以提供账户入口，但用户私有操作属于客户端。管理平台身份和权限必须作为内部访问处理，不能与普通用户角色混淆。

## 9. 发布与优先级策略

### 9.1 MVP 交付顺序

```text
1. 客户端核心流程
2. 用于内容发布的最小管理平台
3. 用于公开入口和法律信息的最小官网
4. 客户端账户、历史和反馈完善
5. 管理平台运营、AI 质量和任务能力
6. 官网帮助、公告和公开内容扩展
7. Windows 优先的三叶桌宠 P0 版本
```

### 9.2 MVP 范围

| 产品 | MVP 必须包含 | 延后功能 |
| --- | --- | --- |
| 客户端 | 首页、搜索、作品详情、一次 AI 对话、推荐卡片、基础账户和收藏 | 高级个性化、作品对比、社交分享、语音；桌宠作为后续 P1 增量 |
| 官网 | 公开首页、产品介绍、客户端入口、隐私、条款和版权信息 | 完整公开内容库、SEO 扩展、公开 AI 演示和下载中心 |
| 管理平台 | 登录、内容编辑、审核发布、基础用户反馈、角色权限和审计记录 | 高级仪表盘、复杂推荐运营、多级审核和自动化报表 |

### 9.3 独立发布规则

- 客户端发布不得展示草稿或未审核内容。
- 官网发布不得暴露内部管理路由或用户数据。
- 管理平台发布必须保留权限和审计规则。
- 任一应用发布前都必须复查共享内容规则。
- 功能只有在用户行为、管理处理、错误状态以及回滚或禁用路径都已定义后，才算完成。

## 10. 架构决策

以下产品决策已针对 MVP 冻结，并记录在 [decision-log.md](../docs/decision-log.md)：

1. MVP 客户端只使用 PC Web，Electron 延后。
2. MVP 同步发布最小公开入口官网，完整公开内容库延后。
3. 官网和客户端共享一个产品账户概念，但私有操作保留在客户端。
4. 官网展示产品信息和选定的公开内容，不复制完整 AI 工作区。
5. MVP 的 AI 只在客户端提供。
6. 首批管理角色为超级管理员、内容编辑、内容审核员、AI 运营、客服运营、数据运营和审计员。
7. 动漫、排期、Banner、图片和外部链接内容必须经过定义的审核边界后才能发布。
8. 客服运营和审计员访问个人数据必须受权限控制并留存记录。
9. 桌宠作为 `sanye_anime` 的 P1 附属形态，先实现 Windows 基础显示、交互、唤起和设置，不独立建设业务后端。

以下事项仍属于外部门禁，不视为产品需求不明确：

- AI 供应商协议、模型成本和最终额度。
- 动漫数据、图片和外部链接的授权证据。
- 域名、托管和生产部署环境。
- 高保真视觉设计资产和最终品牌素材。
